# Eight-week applied Git & GitHub curriculum

**Audience:** Developers learning practical version control, collaboration, CI, recovery and release governance. **Prerequisites:** Git 2.28+, Python 3.10+, shell basics. GitHub login and `gh` are optional for the first six weeks.

The course contains **36 guided lessons, 24 graded offline labs, six workshops, three portfolio projects and 45 interview Q&As**. Plan for **6–9 hours per week**; adjust to experience. Lessons are designed for understanding and repetition, not speed.

## A repeatable session

1. **20–30 minutes** — Read part of a lesson. Predict worktree/index/ref changes on paper.
2. **30–45 minutes** — Reproduce commands in a disposable repository; inspect `status`, `log` and `diff`.
3. **20–30 minutes** — Start or resume a graded lab and run its checker.
4. **10 minutes** — Write a concise explanation and failure/recovery note.

## Milestones

**Foundations:** 12 Basics lessons, eight Basics labs and two workshops.

**Collaboration:** 12 Intermediate lessons, eight Intermediate labs and two workshops. Where GitHub isn't available, prepare a local PR diff and review plan rather than claiming a real hosted review.

**Engineering:** 12 Advanced lessons, eight Advanced labs, two workshops and the release investigation. Treat CI/deployment governance as a reviewed exercise, not a request to deploy automatically.

## Completion

- Review all **36 lessons** and demonstrate the four conceptual sections in each.
- Pass **all 24 graded tasks** through the offline checker.
- Finish all six workshops and three projects (or a well-labeled local simulation where hosted services are unavailable).
- Score at least **80/100** on the practical final assessment and meet all mandatory safety conditions.
- Explain at least **80% of the 45 interview questions** without notes, with a runnable or inspectable Git example where relevant.

Progress is recorded in your own evidence journal; the repository does not require or collect learner accounts.
